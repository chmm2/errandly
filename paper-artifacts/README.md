# Errandly paper: datasets and proof of experiments

This folder holds everything behind the results in the manuscript
*Trust Without Receipts: Collusion-Aware Social Dispatch and Price-Claim Assessment
for Campus Errand Platforms* (`docs/paper/ieee/main.pdf`):

- the raw output of every experiment;
- the simulated datasets the experiments ran on, as CSV;
- the figures as images;
- the run logs;
- the test report and the machine description.

No data about real students is included or was collected. The platform has not been
piloted, so every dataset here is generated by the simulator from a seed, using the
production code of the platform.

```
paper-artifacts/
├── results/      raw output of every experiment (JSON) and its run log (.log)
├── datasets/     the simulated data, exported as CSV
├── figures/      the six result figures of the paper, as PNG
├── proof/        test report, Python environment, hardware
└── MANIFEST.sha256   checksum of every file above
```

## The datasets

All files are plain CSV with a header row. Student and runner identifiers are
synthetic UUIDs (`00000000-0000-0000-0000-000000000001` is student 0). Money is in
rupees.

### `campus_seed1/`: the simulated campus (seed 1)

This is the campus the collusion and dispatch experiments run on: 1,200 students in
24 hostel blocks, with 28 honest close-knit groups and 5 collusion rings planted as
cliques. Each of the 30 seeds in the paper builds a campus like this one.

| File | Rows | Columns |
|---|---|---|
| `students.csv` | 1,200 | `student_id`, `hostel_block`, `home_x_m` and `home_y_m` (position in metres), `planted_group_id` and `planted_group_kind` (`benign` or `ring`, empty if none), `friends`, `closure` (equation 4 of the paper) |
| `friendships.csv` | 4,330 | `student_a`, `student_b` (undirected) |
| `errands_routine.csv`, `errands_coordinated.csv` | 26,355 each | one semester of errands: `errand_id`, `posted_s` (seconds into the semester), `requester`, `kind` (`normal`, `farm` for ring farming, `favour`), `reward_rs`, `collect_rs`, `first_tier` (`1` friends-first, `0` unrestricted), `exploring`, `winner`, `wait_s`, `winner_hops` |
| `payments_routine.csv`, `payments_coordinated.csv` | about 26,300 each | the payment graph: `errand_id`, `payer`, `payee`, `amount_rs` (fee plus collected cash), `at` |
| `offer_rounds_routine.csv`, `offer_rounds_coordinated.csv` | about 80,000 each | the offer log, one row per candidate per dispatch round: `round_id`, `requester`, `exploring`, `accepted_by`, `candidate`, `rank`, `distance_m`, `hops`, `trust`, `effective_score_m` (equation 11) |

In the routine regime friends meet only through the router. In the coordinated
regime each ring partner positions to be the router's first pick before every
farming errand.

### `price_claims/`: one 16-week claim history per attack (seed 1)

These are every claim from one run of the deployed estimator, with 40 runners and
one item whose true price is Rs. 20. Files are named `<strategy>_<share>_seed1.csv`:
`line_300` and `evasive_300` have 30% dishonest runners, `overt_300` has 30% claiming
Rs. 30, and `volume_025` has one runner filing ten times as often.

Columns: `runner`, `attacker` (1 = dishonest), `day`, `true_price_rs`,
`claimed_rs`, `reference_in_force_rs`, `verdict` (`OK`, `ELEVATED`, `FLAGGED`),
`rs_over_reference`, `allowance_rs` (equation 1), `reimbursed_rs`, and
`runner_already_flagged` (whether the walking-the-line rule had already flagged this
runner).

The matching `_reference.csv` file gives the reference price at the start and after
each week. The `line_300` series is identical to the one stored for seed 1 in
`results/exp3_reference.json`.

### `escrow_orders/orders_seed1.csv`

These are the 3,000 orders of escrow seed 1. Columns: `order_id`, `reward_rs`,
`mrp_total_rs` and `mrp_items` (printed-price goods), `loose_total_at_reference_rs`
and `loose_lines` (loose-priced items with quantity and listed price), and
`eligible_reimbursement_rs`, which is what the production judge would reimburse
after drawing a counter price for each loose item.

### `item_names/`

| File | Rows | What it is |
|---|---|---|
| `variants.csv` | 200 | hand-written misspellings of 20 canteen items and what the name normaliser made of them |
| `must_not_merge.csv` | 20 | different items with similar names, which must not be merged into a listed item |
| `adversarial.csv` | 61 | names a runner might type to avoid a check, with the outcome under the old rule and under the deployed claim binding (`JUDGED_SAME`, `JUDGED_OTHER`, `UNCHECKED`, `REFUSED`) |

### `shop_pooling/`

This is the full grid behind Table IX:
- `honest_dear_shop.csv`: honest runners at dearer shops.
- `colluders_cheap_shop.csv`: colluders at a cheap shop, by inflated price, claims per colluder, honest reporters and number of colluders.

## Proof of the runs

- `results/*.log` are the console output of each run, in the order the trials ran.
  In the main collusion logs (`exp2_main_A.log`, `exp2_main_B.log`), every trial line
  also prints the check that the simulator's closure and circulation match the
  production Cypher queries (`diff=0.0e+00/0.0e+00`).
- `proof/pytest-output.txt` and `proof/pytest-junit.xml` are the backend test suite
  run against its own database, Redis and Neo4j: 273 passed. Every test is listed by
  name.
- `proof/environment.txt` lists the Python version and every installed package in the
  backend image.
- `proof/hardware.txt` describes the machine: an Intel Core i7-12650H, 16 threads,
  7.6 GiB available to Docker.

To check that no file has changed since it was published, run this from this folder:

```bash
sha256sum -c MANIFEST.sha256
```

## Regenerating everything

The commands are in `backend/evals/paper/README.md`. The experiments write into
`paper-artifacts/results/`, so the backend container needs this folder mounted at
`/paper-artifacts`. The datasets are regenerated with:

```bash
docker compose run --rm --no-deps -T -v "$(pwd)/paper-artifacts:/paper-artifacts" \
  -e LLM_PROVIDER= backend python -m evals.paper.export_datasets
```

and the figures with `python docs/paper/ieee/figures/make_figures.py`.
